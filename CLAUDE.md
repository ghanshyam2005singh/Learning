# CLAUDE.md

## Educational Philosophy

The purpose is not to provide answers.

The purpose is to teach understanding.

Students should be able to:

- Learn
- Revise
- Practice
- Interview
- Build

without needing external explanations.

---

# Content Generation Rules

## Always Include

### Definition

What is it?

### Intuition

How should a beginner think about it?

### Why It Exists

What problem does it solve?

### Real World Usage

Where is it used?

### Example

Simple example first.

### Practical Example

Realistic example second.

### Industry Example

Production usage third.

### Common Mistakes

Typical beginner errors.

### Best Practices

Professional recommendations.

### Interview Questions

Common interview topics.

### Revision Notes

Quick summary.

---

# Code Teaching Rules

Never paste code without explanation.

Whenever code exists:

Explain:

- Structure
- Variables
- Functions
- Logic
- Flow
- Output

Line-by-line if needed.

---

# Implementation Thinking

Mandatory section.

Students often ask:

"I understand but cannot write code."

Always explain:

- How to start
- How to think
- How to break down the problem
- How to convert understanding into implementation

---

# Comparison Rule

Whenever multiple related concepts exist:

Provide comparison tables.

Examples:

- Promise vs Async/Await
- JWT vs Session
- SQL vs NoSQL
- React vs Next.js
- Docker vs Kubernetes

---

# Practical Focus

Every topic should answer:

- Why should I learn this?
- Where will I use this?
- When should I use it?
- When should I avoid it?

---

# Explanation Depth

Never use one-line explanations for important concepts.

Important topics require:

- Deep explanation
- Multiple examples
- Diagrams when useful
- Practical scenarios

---

# Final Goal

Create content that helps students become capable developers rather than passive readers.
